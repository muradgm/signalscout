# SignalScout Homepage Recomposition V2

Last updated: 2026-04-11

## Purpose

This document replaces the default "clean SaaS homepage" structure with a more advanced, more memorable, and less AI-coded composition.

Companion reset:

- [website-direction-reset.md](C:/Users/Murad/Documents/SS/signalscout/docs/product/website-direction-reset.md)

This document should be used before any further homepage code polish.

## Core Rule

Do not keep iterating the current page section-by-section as if it is fundamentally correct.

It is useful as a prototype.

It is not the final structure.

The next version should be recomposed.

## New Page Logic

The homepage should feel like:

1. a statement
2. a revealed system
3. a product surface
4. a focused fit signal
5. a quiet close

That is different from:

1. hero
2. cards
3. cards
4. product panel
5. cards
6. cards
7. CTA

## New Section Count

Reduce the page to 5 primary movements.

That will make it feel more intentional and less segmented.

## Section 1: Statement Hero

### Goal

Make SignalScout feel like a distinct product brand immediately.

### Structure

- full-width nav
- left-led wordmark area
- strong headline block
- small supporting copy
- restrained CTA row
- one singular right-side visual artifact

### Hero principle

The hero visual should no longer be a stack of small product cards.

It should be:

- one large framed composition
- or one product surface plus one subtle overlay
- with clear breathing room around the headline

### Design intent

This section should feel like:

- a product statement
- not a busy explanation

## Section 2: System Reveal

### Goal

Show how the product thinks without using a conventional feature grid.

### Structure

Use one horizontal or staggered editorial sequence that shows:

- inspect
- signal
- audit
- draft
- decide

### Design intent

This should feel more like a designed rail or annotated sequence than a row of matching cards.

Possible treatments:

- thin horizontal rule with anchored moments
- stepped layout with alternating text
- narrow high-contrast editorial strip

## Section 3: Product Surface

### Goal

Make the workspace feel desirable and credible.

### Structure

Use one dominant product composition.

Do not surround it with too many framed support cards.

Instead:

- one large product surface
- one or two callout annotations
- one supporting line of copy

### Design intent

This should feel almost gallery-like.

The product gets real space.

The page should trust the product enough to let it breathe.

## Section 4: Fit And Credibility

### Goal

Say who this is for and why the product is believable without falling back into a grid of proof boxes.

### Structure

Combine fit and trust into one section.

Possible composition:

- left column: who it is for
- right column: short credibility notes

Or:

- one large statement
- three smaller proof fragments beneath

### Design intent

This section should feel selective, not broad.

It should make the product feel sharper because it is not trying to be for everyone.

## Section 5: Quiet Capability Note + Close

### Goal

Close cleanly while keeping scope honest.

### Structure

Use:

- one short capability note
- one final CTA block

Capability note should say, quietly:

- sending supported
- replies visible
- both secondary to the core review workflow

### Design intent

Do not let this become another feature section.

It should read like confidence, not defense.

## Visual Composition Rules

### Use more

- open space
- asymmetry
- long horizontal tension
- clean empty margins
- fewer but more intentional panels
- larger type moments
- visual silence

### Use less

- repeated boxes
- repeated cards
- stacked product chips
- repeated section intros
- too many borders
- too much small-interface decoration

## Border And Surface Rules

### Surfaces should be rare

Not every idea needs a box.

Use framed surfaces only when:

- the product needs emphasis
- a composition needs containment
- a CTA needs a stronger landing

### Borders should feel structural

Not decorative.

Use:

- thin lines
- quiet containment
- occasional tension

Do not use:

- heavy boxed stacking
- “premium card” repetition

## Typography Rules

### Headline behavior

- fewer headline moments
- stronger headline moments
- more contrast between big type and support copy

### Body behavior

- shorter bodies
- more edited text
- more room around lines

### Brand behavior

- the brand should feel quieter and stronger
- descriptor stays secondary
- top-left lockup should feel intentional, not decorative

## Motion Rules

### Hero motion

If motion is used in the hero, it should be:

- subtle
- spatial
- elegant
- almost architectural

Possible directions:

- quiet parallax planes
- slow reveal of a structured surface
- small offset motion between background and product plane

### Page motion

Motion should be reduced in quantity and improved in quality.

Better:

- fewer reveals
- better timing
- more composed movement

Worse:

- lots of staggered card entrances
- obvious landing-page animation patterns

## Color And Material Use

### Page atmosphere

The background can stay light, but it should feel more designed.

The surfaces should feel:

- premium
- cooler
- quieter
- more like a designed publication or software brand

### Accent use

Accent color should be rarer and more meaningful.

Use it to:

- direct attention
- establish brand memory
- highlight action

Not to:

- decorate every section
- make the site feel more “modern”

## Image Use

Original SignalScout imagery should be integrated as part of the composition, not dropped in as decorative filler.

That means:

- fewer images
- stronger placement
- cleaner crops
- more art direction

The page should not feel like it is trying to prove visual richness.

It should feel like it knows exactly where imagery matters.

## Recommended Build Order

When rebuilding the homepage:

1. recompose the hero
2. replace the workflow cards with a more editorial system reveal
3. simplify the workspace section into one stronger product surface
4. merge fit and credibility into one more selective section
5. reduce the capability note and CTA into a quieter close

## PM Recommendation

The next homepage pass should not be "more polish."

It should be:

- less boxy
- less obvious
- less AI-coded
- more memorable
- more architectural
- more typographic

This is the version of the site that has a chance to feel truly ahead instead of simply well-executed.

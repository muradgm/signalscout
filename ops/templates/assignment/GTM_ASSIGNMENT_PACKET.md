# ASSIGNMENT PACKET

## TASK ID
[GTM-P1-001]

## TASK TYPE
strategy_messaging

## OBJECTIVE
Produce grounded, execution-useful go-to-market output for the assigned objective. All messaging, positioning, launch framing, and commercial recommendations must align with current product truth and approved business direction.

## OWNER LANE
GTM

## SCOPE
In scope:
- messaging
- positioning
- launch framing
- offer articulation
- audience targeting
- sales/supporting copy
- funnel/CTA clarity
- competitive framing if grounded in product truth
- campaign or asset recommendations if explicitly requested

Out of scope:
- inventing product capabilities
- changing product scope
- visual design execution
- frontend or backend implementation
- unsupported pricing claims
- unverified competitor assertions
- brand reinvention unless explicitly assigned
- speculative strategy disconnected from current repo and approved direction

## AUTHORITATIVE FILES
- task bundle assignment file
- current product overview/spec
- approved feature or roadmap reality referenced by the task
- current landing page/site copy if relevant
- approved audience, ICP, offer, or pricing docs if available
- any existing launch/brand/strategy docs explicitly referenced by the assignment
- task-specific decision artifacts if referenced

## CONTEXT
You are the GTM lane. Your job is not to make the product sound good at any cost. Your job is to make the product legible, credible, and commercially usable without drifting from reality. If the product truth is too unclear to support confident messaging, escalate.

## REQUIRED OUTPUT
You must produce all of the following:
- the requested GTM artifact in final usable form
- a structured return artifact written to the assigned task bundle return file
- explicit list of files read
- explicit list of files changed if any
- messaging rationale
- assumptions
- risks
- recommended next action if applicable

## CONSTRAINTS
- do not invent capabilities
- do not use vague marketing filler
- do not claim customer outcomes unsupported by product reality
- do not write copy that depends on features not currently available or explicitly approved
- do not change brand strategy unless explicitly assigned
- do not optimize for hype over credibility
- do not collapse important distinctions between current capability and future intent

## ALLOWED PATHS
- docs/
- ops/
- marketing/
- apps/web content files only if explicitly allowed
- task bundle files for the active task only

## FILES LIKELY TOUCHED
- list exact docs/content files to update if applicable
- if no product files are changed, record the GTM artifact location in the return

## DONE WHEN
The task is done only when:
- the requested GTM artifact is complete and usable
- all product claims align with authoritative product truth
- assumptions are disclosed
- risks and open questions are documented
- the structured return artifact is written to the required task file

## VALIDATION
Validation must include:
- claim-by-claim alignment against authoritative product/source files where relevant
- confirmation that audience/problem/solution language matches the assigned goal
- confirmation that no unapproved feature claims were introduced
- confirmation that CTA and positioning are coherent if part of task scope

## REQUIRED EVIDENCE
The return artifact must include:
- files read
- files changed if any
- final GTM deliverable summary
- source grounding
- claim validation notes
- assumptions
- risks
- recommended next action
- completion status

## ESCALATION CONDITION
Escalate immediately if:
- product truth is too incomplete or contradictory to support reliable messaging
- pricing, launch, or offer inputs are missing but required for the task
- the task requires strategic decisions not contained in the assignment
- authoritative files conflict materially
- stakeholder intent and current product reality do not match
